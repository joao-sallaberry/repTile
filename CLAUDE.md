# RepTile — project notes

RepTile (rep + reptile; the icon is a cute orange T-rex lifting a barbell) is a personal Android-first workout app (gym strength + CrossFit WODs). Expo SDK 57, React Native 0.86, TypeScript, expo-router. See `README.md` for user-facing setup and release steps.

## Keep docs up to date

After any change that affects them, update **both** files in the same task — don't wait to be asked:

- `README.md` — features, requirements, commands, release steps, project structure (user-facing).
- `CLAUDE.md` — architecture, conventions, gotchas (for Claude).

Examples that require an update: new feature or screen, new npm script, new dependency with native code, changed build/release steps, new folder under `src/`, schema change that alters the data model description.

## Design decisions (ADRs)

`docs/decisions/` holds one Architecture Decision Record per significant decision (see its `README.md` for the rules and index). When a task involves a choice that is hard to reverse, changes the data model, adds a native dependency, or picks one option over a reasonable alternative, write a new ADR from `template.md` in the same task and add it to the index. Don't rewrite accepted ADRs: supersede them with a new one. Read the relevant ADRs before changing an area they cover.

## Commands

```sh
npm test             # jest (pure logic: timer engine, PRs, set labels/pairing, target summaries, equipment, illustrations)
npm run typecheck    # tsc --noEmit
npm run lint         # expo lint
npm run db:generate  # drizzle-kit migration after editing src/db/schema.ts
npm run media:fetch  # download exercise illustrations (also on npm install; git-ignored)
npm run android      # dev build (expo-dev-client) on the USB-connected phone
cd android && ./gradlew assembleRelease   # release APK
```

Run `npm run typecheck`, `npm run lint` and `npm test` before calling a task done.

## Architecture

- **Routes** in `src/app/`: `(tabs)/` (index, workouts, history, exercises) uses `NativeTabs`; stack screens `workout/[id]`, `workout/edit`, `session/[id]`, `summary/[id]` ("Treino concluído!", replaces the session screen after finishing: stats, new records with what they beat — `src/features/session/summary.ts` —, exercises, WOD blocks, "Atualizar rotina com estes valores" = `updateRoutineFromSession`, which copies the completed sets/loads into the matching routine items), `history/[id]`, `exercise/[id]`, `locations/index`, `locations/new`, `locations/[id]`, `machines/[id]`, `wod/[id]` (full-screen timer for one WOD block of the session in progress; hides the stack header and draws its own, so Tabata can color the whole screen by phase), `settings`, `welcome`. `welcome` is shown once on first launch (`(tabs)/_layout` redirects while `hasSeenWelcome()` in `src/lib/welcome.ts` is false) and asks for the timer permissions; `settings` (gear on Home) shows the same `TimerPermissionsList` later. Don't put permission prompts on Home. Shared pickers live in `src/components/` (`location-picker`, `machine-picker`, `machine-thumb`, `equipment-menu`, `set-type-dialog`, `set-badge`, `exercise-media`, `block-config-fields`, `time-field`).
- **Data**: local-first SQLite via Drizzle (`src/db/`). Screens read with `useLiveQuery`; writes go through repos (`src/features/workouts/repo.ts`, `src/features/session/repo.ts`, `src/features/places/repo.ts`).
- **Timer** (`src/features/timer/`):
  - `engine.ts` — pure, timestamp-based (`startedAt`, `pausedTotalMs`, `extraSec`); never accumulate ticks. Fully unit-tested. Tabata snapshots carry `interval` (work/rest) and cue `rest`; `skipSegment` ("Pular": next EMOM interval / Tabata segment / end of lead-in) moves `startedAt` back.
  - `store.ts` — single active timer (rest or WOD) in Zustand, persisted to `expo-sqlite/kv-store`.
  - `notifications.ts` — `react-native-notify-kit` (maintained Notifee fork; Notifee was archived in Apr 2026). Foreground service with native chronometer while a timer runs; AlarmManager triggers (`SET_ALARM_CLOCK`) for end/interval beeps **only while the app is backgrounded**; in foreground `cue-player.ts` plays beeps via `expo-audio` to avoid double sounds.
  - `index.ts` (app entry) registers the foreground service and background event handler before `expo-router/entry`.
- **Blocks** (ADR 0010): a workout has no type; it is an ordered list of blocks (`workout_blocks`, `BLOCK_KINDS`: `exercises` | `amrap` | `emom` | `for_time` | `tabata`). Every `workout_items` row belongs to a block (`block_id`, `position` = order within the block). `exercises` blocks hold sets/warm-ups/rest and are shown without a header when they're the only block; WOD blocks hold the timer settings and per-round movements. EMOM `alternate` = one movement per interval in turn (`emomMovementIndex`). Tabata (ADR 0012) has `work_sec`/`rest_sec`/`rounds`, no rest after the last round, and one movement per round in turn (`tabataMovementIndex`). Pure helpers in `src/features/workouts/blocks.ts` (labels, icons, `describeBlockFormat`, `describeShape`, `blockTimerSpec`; tested). Don't reintroduce a workout-level type.
- **Sessions**: starting a workout snapshots each block into `session_blocks` (config + WOD result: `finishedAt`, `result*`, `rx`, `is_pr`, `workout_block_id`) and creates `session_sets` (`session_block_id`; `position` is unique across the session and groups one exercise's sets). Blocks can be done in any order. Exercise sets are completed one by one; a WOD block is run in `wod/[id]` (the card's "Iniciar" starts the timer with `startBlockTimer` and opens it, no intermediate screen; opened without a timer, e.g. "Registrar resultado sem timer", it shows the result form) and `finishBlock` saves its result and marks its movements done; `resetBlock` (restore icon on the card, with confirmation) clears the result, round data and PR flag and un-completes the movements. While it runs, `updateWodProgress` stores per-round data on the block: `round_splits` (AMRAP "+ Round" / For Time "Round feito", elapsed seconds) and `round_reps` (Tabata reps per round, counted with +1/+5/− and editable per round on the result form; the result is the total, the worst round is shown). `src/features/session/wod-runner.tsx` has one view per kind (EMOM dial of 60 ticks, made of plain Views since there's no SVG library; AMRAP rounds; For Time rounds/splits; Tabata work/rest colors). Blocks can be added to any session in progress (`addBlockToSession`) and removed (`removeSessionBlock`); an exercise can be removed (`removeExercise`; the routine is untouched). Volume and load PRs only count sets of `exercises` blocks (`performedSets` joins `session_blocks`). The active timer carries `blockId` for WOD timers. Start sessions through `src/features/session/begin.ts` (`beginRoutine`, `beginFreeWorkout`): it enforces one session in progress at a time. Weights default to **0**, never empty: routine targets are created with 0, and a 0 kg target means "no target" (the session pre-fills last time's load, else 0). The finish dialog lets the user adjust start/end times (`TimeField`, `@react-native-community/datetimepicker`, Android imperative API); `finishSession` accepts `startedAt`/`finishedAt`. A "Treino livre" is a session with `workout_id = null` that starts with one empty exercises block; finishing it can turn it into a routine (`saveSessionAsRoutine`, which also points the session at the new routine).
- **PR flags** (ADR 0009): `session_sets.is_pr` is written by `completeSet` (and re-evaluated by `updateSet`/`setSetType`, cleared by `uncompleteSet`); `session_blocks.is_pr` is set by `finishBlock` for AMRAP/For Time when the result beats every earlier run of the same routine block (`isWodPR`; ADR 0010 moved it from `sessions`). Home/history read these flags instead of recomputing PRs. "N PRs" counts one per exercise per session.
- **Home** (`src/features/home/`): `(tabs)/index.tsx` composes the sections. Three states: first use (no routines, no sessions → `FirstUse` with templates from `src/features/workouts/templates.ts`), session in progress (`ActiveSessionCard`, compact week, last sessions; start options hidden), and normal (`WeekCard`, `StartSection`, `RoutineList`, `RecentPrs`, `RecentSessions`). Queries in `queries.ts`; pure helpers in `stats.ts` (tested): weeks start on **Monday**, `nextInRotation` = routine done longest ago, never-done first (ADR 0008; with blocks every routine takes part). The weekly goal is a per-device setting (`goal.ts`, edited in Ajustes). So is "Descanso após aquecimento" (`src/features/session/preferences.ts`, default on): `startsRest(type, prefs)` decides whether completing a set starts its rest timer; only warm-ups can be excluded.
- **Set types** (`SET_TYPES`: warmup/normal/drop/failure): items of `exercises` blocks store one target row per set in `workout_item_sets` (the `workout_items.sets` column only mirrors the count; WOD block items keep reps/weight on the item). `src/features/session/sets.ts` has the pure helpers: `setLabels` (W, 1, 2, D, F — only normal sets are numbered), `pairPrevious` (the "Anterior" column pairs sets by type + order) and `countsTowardStats` (warm-ups never count for volume/PRs). New warm-ups are inserted after the existing warm-ups, before working sets.
- **Equipment** (ADR 0011, ADR 0015, ADR 0017): `exercises.equipment` is a JSON list of `EQUIPMENT` values (`none` | `barbell` | `band` | `dumbbell` | `suspension` | `kettlebell` | `cable` | `machine` | `other`): never empty, the first is the default; `none` is shown as "Livre" (bodyweight) and combines with the others like any equipment (`toggleEquipment` only keeps the list non-empty). `workout_items.equipment` / `session_sets.equipment` record the one used (resolved to the default when saving a routine or starting a session; `addExerciseToSession` reuses last time's). Pure helpers and labels in `src/features/workouts/equipment.ts` (`equipmentLabel`, `equipmentText`, `defaultEquipment`, `hasStation`, `stationNoun`, `matchesEquipment`; tested); `EquipmentChips` (multi-select) and the `EquipmentFilter` (+ `matchesExercise`, used by the Exercícios tab and the exercise picker; matches any picked equipment) live in `src/components/exercise-picker.tsx`; `EquipmentMenu` (`src/components/equipment-menu.tsx`) switches the equipment of a routine item / session exercise when there are several (`setExerciseEquipment` clears the machine if the new one has no station). The machine picker (routine editor, session) only appears when the equipment used has a station (`hasStation`: `machine` or `cable`, ADR 0014) or a machine is already set; for cable the UI says "polia" (`stationNoun`, `MachinePicker`'s `noun`). `linkMachineToExercise` adds `machine` to the exercise's list unless it already has a station equipment. Seed equipment comes from `seed.ts` (new installs) and migrations 0005/0009/0010/0011 (existing ones); seeding never overwrites it.
- **Exercise illustrations** (ADR 0016): RepDB free tier, pinned commit. `src/features/exercises/media-map.json` (committed, ids only) maps seed exercise id → equipment → RepDB id; `pickMediaId` (`media-map.ts`, tested) falls back to the first mapped equipment. `scripts/fetch-exercise-media.mjs` (`postinstall`, `npm run media:fetch`) downloads the mapped images to `assets/exercise-media/` and writes `src/features/exercises/media.generated.ts` (`FRAMES`: RepDB id → `require()`d start/peak or main poses); **both are git-ignored and must never be committed** (the repo is public and the license forbids redistributing the images as a dataset), never fed to generative-AI tools, and the "Exercise data by RepDB (repdb.co)" credit in Ajustes (Créditos) must stay. When adding a seed exercise, add its media ids to the JSON and run `npm run media:fetch`. `src/components/exercise-media.tsx`: `ExerciseMedia` (animated only on `exercise/[id]` and the workout card's "how to" dialog), `ExerciseThumb` (still, with a placeholder; exercise lists), `hasExerciseMedia`.
- **Locations & machines**: `locations` (gym/box), `machines`, `location_machines` (N:N) and `machine_exercises` (N:N). Machines are optional and any machine can be used for any exercise: `MachinePicker` lists all of them (`machinesForExercise`: used for this exercise, at this location, others) and picking/creating one links it to the exercise (`linkMachineToExercise`, also from the routine editor) and to the session's location. `workouts.location_id` is the routine's fixed location (optional); `sessions.location_id` is where it was done (falls back to the per-device current location, `src/features/places/current.ts`). `workout_items.machine_id` / `session_sets.machine_id` record the machine. "Anterior", pre-filled loads and PR checks are per exercise **+ equipment + machine** (`performedSets(exerciseId, { equipment, machineId })`: `undefined` = any, `machineId: null` = no machine); the exercise screen filters history per variant (equipment + machine); a machine's history is shared across all its locations.
- **Machine photos** (`src/features/places/photos.ts`; taken on `machines/[id]`, reachable from the camera/info button of each row of `MachinePicker`, the "Máquinas" card of `exercise/[id]` and `locations/[id]`): `expo-image-picker` (camera or gallery) → `expo-image-manipulator` downscales to 800 px on the longest side, JPEG 0.6 (~50–100 KB) → moved into `<document>/machine-photos/`. `machines.photo` stores only the file name (resolve with `machinePhotoUri`); file names carry a timestamp so `expo-image` doesn't show a cached old photo, and the previous file is deleted on replace/remove. Photos are local only — they won't sync until uploaded to Supabase Storage.
- Migration `0011` adds "Livre" to Afundo and "Halter" to Afundo lateral (and makes it load × reps), only if unchanged.
- Migration `0010` merges "Supino com halteres" into "Supino reto" (dumbbell variant: moves sets, routine items and machine links, soft-deletes the old exercise; `seed.ts` no longer has it) and adds equipment to a few seed exercises.
- Migration `0009` turns `exercises.equipment` into a list (drizzle rebuilds the table) and backfills `workout_items.equipment` / `session_sets.equipment` from the exercise.
- Migration `0007` soft-deletes `session_sets` without `session_block_id` (created by a bug in `addSet`; every set must carry its block or the session screen won't show it).
- Migration `0004` (blocks) wipes routines and history (agreed while testing) instead of converting them; exercises, locations and machines are kept.
- Migration `0001` expands the old "N sets of R reps" strength items into `workout_item_sets` rows (hand-written SQL appended after the generated DDL). Hand-edit migrations only by appending, and test them in SQLite (e.g. Python `sqlite3`) before shipping.

## Conventions

- **Language**: code, comments, tests and docs in English; **app UI strings in Portuguese** (pt-BR).
- Every table has sync columns (`id` UUID, `userId`, `createdAt`, `updatedAt`, `deletedAt`, `dirty`) for the planned Supabase sync. Use `createdFields()` / `touched()` from `src/lib/ids.ts`; delete with soft delete (`deletedAt`), and filter `isNull(deletedAt)` in queries.
- **Paper `Card`** passes `index`/`total` props to its direct children: wrap optional children in a `View`, not a Fragment (dev warning). Card title actions use 20 px `IconButton`s without margin (`compactIcon`) so titles like "EMOM 12 min · alternado" fit; tabs use `labelVisibilityMode="labeled"` (Android hides unselected labels with 4+ tabs otherwise).
- **Edge-to-edge**: Android draws under the system navigation bar. The root `Stack` pads every stack screen with the bottom safe-area inset (`contentStyle`); `(tabs)` (NativeTabs handles it) and `welcome` (own `SafeAreaView`) opt out. New full-screen routes without a header must handle insets themselves.
- Seed exercises use fixed IDs `seed-<slug>` (`src/db/seed.ts`); the seed runs on every launch with `onConflictDoNothing`, so new seed exercises reach existing installs. One exercise per movement: variants that only differ in equipment are one exercise with several equipment (ADR 0015), not separate seeds.
- Never edit `android/` or `ios/` by hand (generated by `expo prebuild`); use `app.json` and config plugins in `plugins/`. Notification sounds live in `assets/sounds/` and are copied to `res/raw` by `plugins/with-raw-sounds.js`.
- Install packages with `npx expo install`.
- App icons and splash in `assets/images/` are generated from the mascot art `assets/icon/mascot.png` (dino + "RepTile" wordmark on off-white) by `python3 assets/icon/render.py assets/images [preview_dir]` (needs Pillow). The script crops off the wordmark, flood-fills the outer background (plus the floor shadow around the feet) to transparent, and builds the adaptive layers (off-white `#FDFCF9` background, matching `adaptiveIcon.backgroundColor` in `app.json`), a monochrome layer with the dark details cut out, and the splash. If the art changes, re-check `DINO_BOTTOM` / `SHADOW_BOX` and the previews. Don't edit the PNGs by hand. Gradle builds don't pick up icon/splash changes on their own: run `npx expo prebuild --platform android --clean` first.
- Android package / iOS bundle id: `dev.joaosallaberry.reptile` (was `com.joao.reptile` while testing). Changing it installs a separate app (data not migrated), so avoid it once there's real data, and it's impossible after publishing to the Play Store.

## Build environment gotchas (this machine)

- Only 6.5 GB RAM. `~/.gradle/gradle.properties` limits Gradle (2 workers, in-process Kotlin, arm64 only). `~/Android/Sdk/cmake/3.22.1/bin/ninja` is a wrapper forcing `-j4` (real binary: `ninja.real`); recreate it if CMake is updated.
- Use **JDK 17** (`JAVA_HOME=$HOME/.local/jdk-17`). Android Studio's bundled JBR is Java 25 and breaks prefab (`WARNING: A restricted method in java.lang.System has been called`).
- Dev build (`expo-dev-client`, ADR 0013): JS loads from Metro (`npx expo start`) over Wi-Fi; the launcher lists LAN servers and reconnects to the last one. Prefer it over release builds for testing JS changes. Debug APK without Metro: `cd android && ./gradlew assembleDebug`. Over USB, `adb reverse tcp:8081 tcp:8081` still works after the phone locks/reconnects.
- Release builds are signed with the debug keystore (fine for sideloading; installs over the dev build keeping data).
