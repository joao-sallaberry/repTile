# 0001. React Native + Expo with development builds

- **Status:** Accepted
- **Date:** 2026-10-05

## Context

The app is Android-first, with iOS as a possible later target. Options were native Kotlin or React Native + Expo. The rest timer and WOD timers must notify reliably with the screen off, which needs a foreground service and exact alarms — not available in Expo Go.

## Decision

React Native + Expo (TypeScript, expo-router), run as a **development build** (`npx expo run:android`), not Expo Go. Native behaviour is configured through `app.json` and config plugins; `android/` is generated by `expo prebuild` and never edited by hand.

## Consequences

- One codebase for Android and a future iOS build.
- Any library with native code needs a new dev build / release build; Expo Go can't run the app.
- Builds happen locally (JDK 17, low-memory Gradle settings), not on EAS.
